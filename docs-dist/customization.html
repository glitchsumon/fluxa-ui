Customization

Three levels of customization: theme tokens, local overrides and component re-skinning.

1. Token override

The most powerful option. Override semantic tokens in your own stylesheet loaded after Fluxa. Every component follows instantly.

CSS
:root {
  --fx-color-primary: #0f766e;                 /* brand teal */
  --fx-color-primary-hover: #115e59;
  --fx-radius-md: 12px;
  --fx-font-sans: 'Inter', system-ui, sans-serif;
  --fx-space-4: 1.25rem;
}

:root[data-theme='dark'] {
  --fx-palette-surface: #0f1220;               /* dark surfaces stay deliberate */
  --fx-palette-border: #24283b;
}

2. Component CSS variables

Several components expose their own variables for surgical tweaks:

ComponentVariables
Button--fx-btn-bg · --fx-btn-color · --fx-btn-border
Card--fx-card-bg · --fx-card-border
Avatar--fx-avatar-size · --fx-avatar-bg · --fx-avatar-color
Sidebar--fx-sidebar-width
Progress--fx-progress-value · --fx-ring-color

3. Local overrides

Specificity stays low by design, so your own rules rarely need !important:

CSS
.my-hero .fx-btn-primary {
  padding-block: 1rem;
  border-radius: var(--fx-radius-lg);
}

/* feature a section with a custom card accent */
.workspace .fx-card {
  --fx-card-border: var(--fx-color-primary);
}
Keep tokens in one place
Avoid sprinkling raw hex values across your stylesheet — route everything through the token layer for a themeable result.
